# Tsukiori V1.0.0-rc.1 已知问题与发布边界

评估日期：2026-08-02

## 发布前置条件

- 公共仓库和公共 CI 不保存 Windows Code Signing Certificate 或私钥。
- 正式发布必须在受控发布环境注入可信 Authenticode 证书；`package:win:release` 启用 `forceCodeSigning`，缺少证书时 fail closed。
- 本地与公共 CI 生成的未签名 NSIS 只用于工程验证，不上传、不发布，也不称为可发布 Artifact。
- 发布时还必须生成 Ed25519 detached Release Manifest，并通过 HTTPS Origin、Channel、文件名、Byte Length、SHA-256 和数据库 Schema 策略。

## OpenCode 1.18.4

- 运行中 Turn 的 Server 崩溃恢复未验证，保持 `unknown`；Host 不自动重放 Prompt 或高风险操作。
- Provider 配置存在 key-like 字段名；Fixture、事件、日志和诊断包不保留值。
- Global SSE 必须显式关闭；Adapter 已实现关闭路径，异常断线时通过 Snapshot 与恢复状态说明缺口。

## Codex 0.146.0

- 0.142.5 被当前模型服务拒绝，V1 只接受锁定 Schema Hash 的 0.146.0。
- 本机 WebSocket Sampling 曾超时并降级为 HTTPS；该诊断不伪装成 Turn 失败。
- 未观察到 structured network approval，支持与 Enforcement Level 保持 `unknown`。

## 平台与安全边界

- V1 只承诺 Windows Native x64；WSL、macOS、Linux、Claude Adapter 与 Generic ACP 属于 V1 后任务池。
- Worktree 是变更隔离机制，不是安全沙箱；`observable_only` 和 `opaque` 不表示 Host 已拦截。
- 本机工作区的 Electron 解压目录曾被文件扫描器短暂锁定；RC/CI 构建使用全新系统临时目录，Artifact 内容与验证规则不变。
