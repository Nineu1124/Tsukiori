# Tsukiori V1.0.0-rc.1 已知问题与发布边界

评估日期：2026-08-03

## 发布通道

- 公共仓库和公共 CI 不保存 Windows Code Signing Certificate 或私钥。
- Local V1 允许发布未签名 NSIS；Release 页面和安装说明必须明确提示 Windows SmartScreen 可能显示“未知发布者”。
- Local V1 仍必须生成 Ed25519 detached Release Manifest，并通过 HTTPS Origin、Channel、文件名、Byte Length、SHA-256 和数据库 Schema 策略。
- 可选 Verified Publisher 通道使用 `package:win:release` 和 `forceCodeSigning`；缺少可信 Authenticode 证书时该通道 fail closed，但不阻塞 Local V1。

## Provider 与凭据

- OpenAI、Anthropic、DeepSeek 和两类自定义兼容 Provider 均必须由用户显式配置；没有相应 API Key 时不得显示为 connected。
- API Key 只存放于 Windows Credential Manager。设置状态、SQLite、日志、诊断包、导出、Renderer Snapshot 和公开 Fixture 只保留脱敏状态，不保留 Key 或可反查的认证内容。
- 自定义 OpenAI-compatible Provider 必须实现 Codex 所需的 Responses API；仅实现 `/v1/chat/completions` 或仅能通过 `/v1/models` 探测，不代表可完成 Codex Turn。
- 自定义 Anthropic-compatible Provider 的连接测试会发送 `max_tokens=1` 的最小 Messages 请求并丢弃响应正文；这只是连通性验证，不承诺全部 Claude 原生能力。

## OpenCode 1.18.4

- OpenCode Adapter 的协议验证仍保留，但当前普通交互界面不允许使用 OpenCode 创建 Session，支持级别保持 `unknown`。
- 运行中 Turn 的 Server 崩溃恢复未验证，保持 `unknown`；Host 不自动重放 Prompt 或高风险操作。
- Provider 配置存在 key-like 字段名；Fixture、事件、日志和诊断包不保留值。
- Global SSE 必须显式关闭；Adapter 已实现关闭路径，异常断线时通过 Snapshot 与恢复状态说明缺口。

## Codex 0.146.0

- 0.142.5 被当前模型服务拒绝，V1 只接受锁定 Schema Hash 的 0.146.0。
- 当前开发运行版优先使用本机忽略目录中的 `0.146.0` Runtime；其他机器必须自行安装兼容 Codex，安装包不携带用户认证或私有 Runtime。
- 本机 WebSocket Sampling 曾超时并降级为 HTTPS；该诊断不伪装成 Turn 失败。
- 未观察到 structured network approval，支持与 Enforcement Level 保持 `unknown`。

## Claude Code 2.1.201

- Local V1 使用官方 CLI `stream-json` 接入，整体支持级别为 `degraded`，不等同于 B1 的完整 Claude Adapter。
- 权限只映射 Plan、Accept Edits 和 Don't Ask；Hooks、Skills、MCP、Subagents、Checkpoint 与细粒度 Approval 仍未通过统一 Adapter Contract，保持 `unknown` 或后续任务状态。
- Claude Session 可选择 Anthropic、DeepSeek 或 Anthropic-compatible Provider，但 Provider 兼容性和模型可用性仍取决于实际服务端；不兼容组合必须在创建 Worktree 前失败。
- 同名 Bun 可执行文件不得被误识别为 Claude Code；版本探测必须同时验证官方 CLI 身份和版本。

## 平台与安全边界

- V1 只承诺 Windows Native x64；WSL、macOS 和 Linux 属于 V1 后任务池。
- Session、项目和 Thread ID 可恢复；为避免未经同意持久化完整 Prompt，当前版本重启后不恢复完整对话正文。
- Worktree 是变更隔离机制，不是安全沙箱；`observable_only` 和 `opaque` 不表示 Host 已拦截。
- 本机工作区的 Electron 解压目录曾被文件扫描器短暂锁定；RC/CI 构建使用全新系统临时目录，Artifact 内容与验证规则不变。
- Runtime、Daemon 与 Named Pipe Host 在正常退出和强制终止路径都必须回收；测试结束后残留孤儿宿主视为回归失败。
