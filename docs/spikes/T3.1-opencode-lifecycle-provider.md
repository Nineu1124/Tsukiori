## Checkpoint 证据

### T3.1-C1 自动发现路径、版本和认证来源

- 发现顺序为 `OPENCODE_BIN`、npm global 原生 `opencode.exe`、PATH `opencode.exe`。
- 路径经 `realpath` 规范化；数据库与报告只使用不可逆 SHA-256 指纹作为公开证据。
- `--version` 和 `auth list` 使用结构化参数、无 Shell 拼接、超时和输出大小限制。
- 精确锁定 1.18.4；更高版本为 `unverified_newer`，更低版本为 `incompatible_older`，未认证为显式 `none`。
- Fixture 覆盖版本、无认证、发现来源与重新 Probe；真实 Probe 返回 `supported` 和 `authenticated: true`。
- 结果：通过。

### T3.1-C2 独立 Worktree Scope Server

- 每次 `start` 只绑定 `127.0.0.1` 和随机端口，生成独立随机 Server 密码。
- 密码只进入子进程环境，不进入参数、数据库或审计明细。
- 启动后验证 `/doc`、`/global/health`、`/path`、`/vcs` 和 Provider Catalog。
- `/path` 必须与请求 Worktree 的规范路径一致，否则 fail closed。
- 自动化测试同时启动两个真实 Git Worktree，PID 不同且均可正常停止；错误 OpenAPI 和错误 Worktree Scope 均导致 Handle 为 failed。
- 结果：通过。

### T3.1-C3 Provider 数据出口启动前展示

- Catalog 仅投影 Provider/Model ID、展示名、连接状态、凭据来源、出口 hostname 与 SupportLevel。
- 正式 Host 不调用可能返回 Provider 机密配置的接口，未知出口保持 `unknown`。
- Desktop Runtime 卡片使用原生 `select` 展示 Provider 与 Model，并在任何模型请求前显示 `数据出口：api.deepseek.com` 和 `模型请求尚未启动`。
- Renderer 只使用 `textContent` 和 `option.textContent`；未使用 `innerHTML`、`insertAdjacentHTML` 或 `eval`。
- Electron smoke 观察到 `dpsk`、`deepseek-v4-flash`、`api.deepseek.com` 与 `modelRequestStarted=false`。
- 结果：通过。

### T3.1-C4 DeepSeek 真实会话与凭据边界

- `npm run probe:opencode-adapter` 使用正式 Adapter 创建临时验证 Session，并指定 `dpsk/deepseek-v4-flash`。
- 文件编辑、Shell 和外部目录权限均设为 deny；验证只要求固定短回复且禁止工具。
- 真实会话完成，出口为 `api.deepseek.com`，随后删除验证 Session 并停止 Server。
- Host 只记录完成布尔值和消息数量；不保存 Prompt、输出或 Runtime Session ID。
- 持久化内容扫描未发现测试 Prompt、Server 密码、Authorization、Basic token 或常见 API Key 形式。
- 结果：通过。

## 失败注入与恢复

| 注入 | 预期 | 实际 |
| --- | --- | --- |
| OpenAPI body 与锁定 Hash 不同 | 启动失败 | Handle 标记 failed，Server 被终止 |
| Server 报告其他 Worktree 路径 | fail closed | 启动失败，不返回可用 Handle |
| Runtime 版本高于 1.18.4 | 不按已验证能力运行 | `unverified_newer`，拒绝启动 |
| Runtime 版本低于 1.18.4 | 不兼容 | `incompatible_older`，拒绝启动 |
| 无 CLI 认证条目 | 明确降级 | `authenticated=false`、`authSource=none` |
| Provider 不存在或未连接 | 禁止选择 | 返回稳定 Adapter 错误 |

## 安全边界

- API Key、认证文件、Cookie、Server 密码、完整 Prompt、模型输出、用户源码和原始事件均不提交。
- Provider endpoint 只保存 hostname，不保存带查询参数、认证信息或路径的 URL。
- Runtime stdout/stderr 不持久化，只记录字节数和退出状态。
- Provider 输出、终端输出和展示名均按不可信文本处理。
- Worktree 只提供变更隔离，不被描述为安全沙箱。
