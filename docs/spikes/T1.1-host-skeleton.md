规则与证据：

- Protocol 不依赖任何应用包。
- Desktop、Daemon、Testkit 只依赖 Protocol，不互相引用应用包。
- Desktop 通过启动已构建的 Daemon entry 建立进程边界，而不是导入 Daemon 内部代码。

- `tests/host/package-boundary.test.mjs` 解析实际 package manifest 和构建图，违反方向即失败。
- 结果：通过。

## T1.1-C2 Renderer 与 Preload 安全边界

BrowserWindow 固定设置：

```ts
nodeIntegration: false
contextIsolation: true
sandbox: true
webSecurity: true
```

额外边界：

- 禁止新窗口；非当前页面导航被阻止。
- Renderer 使用严格 CSP，`connect-src 'none'`。
- Preload 只暴露冻结的 `window.tsukiori`：
  - `versions()`
  - `daemon.status()`
- Preload 只调用 `host:versions` 和 `daemon:status` 两个固定 `ipcRenderer.invoke` channel。
- 不暴露 `ipcRenderer.send/on`、Node 文件系统、网络、子进程或任意 channel。
- 静态边界测试检查配置和 Preload 源码；真实 Electron smoke 同时回报三项隔离开关。
- 结果：通过。

## T1.1-C3 Desktop 管理指定 Daemon 版本

Bootstrap 生命周期：

1. Desktop 使用独立 OS 进程启动 `apps/daemon/dist/main.js`。
2. Daemon 输出单行 `daemon.ready`，包含 Daemon 版本、Protocol 版本、instanceId 与 PID。
3. Supervisor 同时校验 `daemonVersion === 0.1.0` 和 `protocolVersion === 1`。
4. `daemon.probe` 返回相同 instanceId/PID，证明检测的是同一进程。
5. `daemon.shutdown` 携带 expectedVersion；Daemon flush `daemon.stopping` 后退出。
6. 版本不匹配时 Supervisor 终止进程并拒绝启动。

T1.1 使用受限 stdin/stdout JSONL bootstrap，仅用于进程启动、探测和停止。它不是 T1.2 的正式本机 IPC，也不提供权限边界。

自动测试覆盖：

- 正确版本 start → detect → probe → stop；
- 错误版本拒绝并终止；
- 停止后 Supervisor 快照清空 PID、instanceId 和版本。
- 结果：通过。

## T1.1-C4 Renderer 崩溃不终止 Daemon

真实 Electron smoke：

1. 启动隐藏 BrowserWindow 和独立 Daemon。
2. 等待 Renderer 完成加载。
3. 调用 `webContents.forcefullyCrashRenderer()`。
4. 收到 `render-process-gone`，原因为 `crashed`。
5. Desktop Main 通过 Supervisor 再次 probe Daemon。
6. Daemon 返回 0.1.0 / Protocol 1，状态仍为 running。
7. 测试最后显式停止 Daemon 和 Electron。

这证明 Renderer 与 Daemon 没有父子生命周期直连。T1.1 尚未承诺 Desktop Main 自身崩溃后的 Daemon 回收；该策略由后续 Supervisor、Job Object 与 Recovery 任务完成。
- 结果：通过。

## 失败与修正记录

1. 首次 workspace 安装因 pnpm 自动生成未决的 node-pty build policy 而返回非零。决策：显式 `electron: true`、`node-pty: false`；node-pty 的官方预编译文件已在 T0.3 验证，无需执行构建脚本。
2. Electron 官方 GitHub Release 在本机不可达。决策：只为本机安装过程设置 `ELECTRON_MIRROR`，仍由 Electron 官方 installer 和 checksum 验证；仓库不固化用户网络代理或凭据。
3. 首次 typecheck 中依赖包声明尚未构建且 Daemon/Testkit 未声明 Node 类型。决策：typecheck 依赖 `^build`，Node 进程包显式使用 `types: ["node"]`。
4. 首次生命周期测试中 Daemon 回复 stopping 后 stdin 仍使进程保持活动。决策：先关闭 readline、pause stdin，再在 stdout flush callback 中退出。修正后 host tests 6/6 通过。
5. Renderer smoke 的初次失败与同一个 Daemon shutdown 缺陷有关；Renderer 崩溃后 Daemon probe 实际成功，修正退出后 Electron 进程也正常返回 0。

## 安全与后续边界

- Daemon 日志不输出输入正文、凭据或环境内容。
- Renderer 不持有 Node 能力，也不能发送任意 IPC。
- Bootstrap 消息字段由 Protocol 包进行结构验证。
- 本任务没有实现 Named Pipe ACL、Peer Identity 或 challenge-response；这些保持为 T1.2 未完成项。
- Desktop Main 崩溃后的孤儿 Daemon 识别与常驻策略仍由后续任务实现。
- 当前 Renderer 是最小静态壳；完整 Vue/Vite UI 属于后续基础 UI 任务。
