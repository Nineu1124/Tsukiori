## Checkpoint 证据

### T0.3-C1 当前用户 Named Pipe 与 Daemon 重连

- server 使用 `PipeOptions.CurrentUserOnly | PipeOptions.Asynchronous`。
- 通过 `PipesAclExtensions.GetAccessControl` 读取有效 ACL。
- owner SID 与当前 SID 相同；DACL 只有一个 Allow 规则，主体为当前 SID，权限为 FullControl。
- 两个独立 PowerShell client 分别收到 `ack:first` 与 `ack:second`。
- 第一个 client 断开后 server 进程仍存活，第二个 client 成功重连；server 共接受两次连接后正常退出。
- 公开 Fixture 只保存 `currentUserOnly=true`、规则数量和重连结果，不保存 SID 或 SDDL。
- 结果：通过。

### T0.3-C2 Job Object 与 PID 复用保护

- 创建带 `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` 的 Job Object。
- 父进程在加入 Job 后再创建子进程；父子 PID 均在关闭 Job 前被观察为存活。
- 关闭 Job handle 后父子进程都在超时前退出。
- 进程身份指纹固定为 `pid + startedAtTicks + executable`。
- 以同一 PID、错误启动时间构造陈旧身份，匹配函数拒绝执行；对应无关进程保持存活。
- 测试没有强制操作系统真实复用某个 PID；它直接验证真实复用时所依赖的等价拒绝条件。正式实现仍应持有进程 handle，并在任何按 PID 的补偿操作前复核完整指纹。
- 结果：通过。

| 强杀目标 | 存活进程 | 协调结果 |
| --- | --- | --- |
| GUI | Daemon、Runtime | `gui_down_control_and_runtime_alive` |
| Daemon | GUI、Runtime | `daemon_down_runtime_orphaned` |

## 失败案例与修正

1. `NamedPipeServerStreamAcl.Create` 的显式安全描述符路径在本机返回拒绝访问。改用 .NET 的 `CurrentUserOnly` 安全选项后成功，并读取实际 ACL 验证不是仅凭选项名称推断。
2. pnpm 默认拒绝依赖构建脚本。使用 `pnpm approve-builds node-pty` 生成 `allowBuilds.node-pty=true`，没有批准其他包。
3. 最初的一次性 `PowerShell -Command` PTY 探针没有可靠退出。改为真正的交互模式：等待标记后写入 `exit`，并保留超时强杀。
4. 直接复制 pnpm junction 会尝试创建 symlink，非管理员环境返回 EPERM。Harness 先 `realpath` 到虚拟存储，再复制最小运行包。
5. node-pty 原生模块可能保留事件循环 handle。Harness 在所有 finally 清理完成、结果写入后显式退出，避免测试 runner 悬挂。

## 安全说明

- Pipe 的真实 SID 与 SDDL 仅存在于随机临时目录，公开 Fixture 不保存。
- Job、强杀和 PTY 测试只操作 Harness 自己创建并持有的进程。
- 删除仅针对经过前缀验证的 `C:\tmp\tw-*` 随机目录和随机系统临时目录。
- Worktree 是 Git 隔离机制，不被描述为安全沙箱。
- 终端输出被视为不可信；公开结果只保留布尔值、版本、Hash 和状态枚举。
