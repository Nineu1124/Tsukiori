## 总结

新增 `@tsukiori/observability`，提供统一 V1 Resource Budget、可取消 Resource Lease、结构化安全日志和 gzip JSON 诊断包。Runtime/PTY 并发、事件队列与载荷、Blob、Diff、日志条目和日志 Ring 均有固定上限；达到上限时明确返回 `ResourceLimitError`，不会无界增长。

诊断包默认排除源码、完整 Prompt、Raw Payload、凭据和认证存储。用户只有显式勾选“包含再次脱敏的敏感预览”后才会加入有界 Preview；Host 在导出前给出预计未压缩大小，Renderer 只发送布尔选项，不接触原始敏感数据。

## T5.3-C1 资源上限

| 资源 | V1 上限 |
| --- | --- |
| Runtime | 同时 3 个 |
| PTY | 同时 8 个 |
| Event | 单条 64 KiB，队列 1024 |
| Blob | 单对象 10 MiB |
| Diff | 单次 2 MiB |
| Log | 单条 16 KiB，Ring 256 条 |

Resource Lease 支持显式 release 和按资源类型 cancelAll。测试占满 3 个 Runtime 和 8 个 PTY 后验证下一请求可解释失败；Event Queue、Event/Blob/Diff/Log Bytes 的边界值成功、越界值失败；取消三个 Runtime 后活动计数归零。

结果：通过。

## T5.3-C2 持久化前安全处理

- Structured Logger 在调用 Sink 前递归替换敏感键、凭据形态和已登记 Secret；
- ANSI、C0/C1 和 Bidi 控制字符在日志持久化前移除；
- 超限日志只保留有界 Preview 与 Content Hash；
- Ring 满后丢弃最旧记录并累计 `dropped`；
- Diagnostic Builder 对 versions、metrics、logs 和 opt-in Preview 全部再次使用同一安全 Logger；
- SQLite/WAL/Blob 继续由 Database SecretGuard 在写入前拒绝 Secret；
- Runtime Native Event 继续先脱敏、后字节限额、再进入持久层。

结果：通过。

## T5.3-C3 默认安全诊断包

`.json.gz` 诊断包默认只包含：Schema、版本摘要、数值指标、已脱敏结构化日志、Drop 计数和明确排除清单。即使调用方同时传入完整 Prompt、源码和 Raw Payload，未勾选时这些值也不会进入 Bundle。

测试解压默认 Bundle，确认不存在敏感 Preview 字段、Fixture Prompt/Source 或 Secret。

结果：通过。
