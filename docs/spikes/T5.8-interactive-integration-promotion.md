# T5.8 新工作台 Integration Worktree 与显式 Promotion 补充报告

日期：2026-08-10
平台：Windows 10 x64

## 结论

RC6 之前已经具备成熟的 `IntegrationMergeService` 合同和包级测试，但新的可交互工作台只展示 Stage、Unstage、Commit 与 Checkpoint。旧 `integrate` 入口位于隐藏 Smoke 页面，生产工作台没有可用入口，实际 IPC 会落到 `unsupported_command`。这意味着 Agent 的提交虽然保存在独立 Session Worktree，却无法从当前 UI 安全落回项目分支。

本轮补齐生产链路：审阅面板读取项目主工作区的当前本地分支与 HEAD，Session Worktree 必须无未提交内容或进行中的 Git 操作；Merge/Rebase 先在用户数据目录下的受管 Integration Worktree 执行，关闭 Hooks 与 Commit Signing，并运行 `git diff --check`。只有验证通过的结果才显示 Promotion；Promotion 再次要求目标分支、HEAD 与验证时一致，要求主工作区干净，先创建 `refs/tsukiori/recovery/promotion-*`，最后执行 `git merge --ff-only`。

## 可观察行为

- 审阅面板显示当前目标分支、目标 Commit 与主工作区是否干净。
- Merge 与 Rebase 都不会在验证阶段修改项目主工作区或分支 HEAD。
- 冲突 Worktree 仅能通过受校验的 Main Process IPC 打开；用户解决并 Stage 后可继续。
- `git diff --check` 失败时保留 Worktree，修复并提交后可以重新验证。
- 目标分支或 HEAD 在验证后变化会拒绝 Promotion，要求重新生成 Integration。
- Promotion 成功后记录结果 Commit 和恢复引用；不保存 Diff、Commit Message、源码或命令输出。
- 丢弃操作需要明确确认，只删除该 Integration 的受管 Worktree 与 Branch，不删除 Session Worktree。
- 应用在 `preparing` 状态退出后，重启会标记为 `interrupted`，不会显示为已验证或已 Promotion。

## 安全与失败边界

- 所有 Git 调用使用 `spawnSync('git.exe', args)`、`shell:false`、固定超时和输出上限，不拼接 Shell 字符串。
- Session Worktree、Project Git Root 与 Integration Path 都经过 `realpath` 和 Git Top Level 校验；Integration Path 必须同时满足词法与规范路径位于受管 Root 内。
- Source 必须 Clean，Submodule gitlink 默认拒绝，Merge/Rebase/Promotion 禁用 Hooks，自动 Merge Commit 禁用 GPG Signing。
- Promotion 仅接受记录中验证过的结果 Commit，并要求主工作区 Clean、目标 Branch/HEAD 未变化；恢复引用在写入目标前创建。
- 持久化文件只含 ID、路径、Commit Hash、状态、冲突相对路径、错误类别和时间；不含 Provider 凭据、Prompt、源码、Diff 或 Git stderr。
