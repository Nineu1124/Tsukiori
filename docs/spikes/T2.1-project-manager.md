# T2.1 Execution Environment 与 Project Manager 实施报告

- 任务：T2.1
- 完成日期：2026-08-02
- 平台：Windows x64
- Project Manager：0.1.0
- Database Schema：v4
- 系统 Git：2.47.1.windows.1
- Git 路径：`C:\Program Files\Git\cmd\git.exe`

## 结论

T2.1 的四个 Checkpoint 均已实现。新增 `@tsukiori/project-manager`，提供 Windows Native Execution Environment Registry、系统 Git Probe、Project 注册/移除/重探测和统一环境一致性验证。所有 Git 命令通过 `execFile` 和参数数组执行，`shell: false`；不拼接 Shell 字符串。数据库 v4 持久化 canonical Git 路径、版本、实际探测的能力、canonical git dir、当前/默认分支、remote 数量、dirty 状态和最后探测时间。

V1 Registry 只注册 `windows-native`。Windows 项目、Git、Runtime 与 Worktree 必须绑定同一 Environment ID；Windows 路径与 WSL UNC、`/mnt/*`、POSIX 可执行文件混用时明确抛出 `EnvironmentBoundaryError`。

## T2.1-C1 添加、移除和重新探测

测试使用本机 Git 在系统临时目录创建隔离仓库：

1. `add` 解析 real path、Git top-level、absolute git dir、repository identity、分支、remote 和 dirty 状态并持久化；
2. 写入一个未跟踪 Fixture 文件后 `reProbe`，dirty 从 false 变为 true，探测时间前进；
3. 相同 canonical git dir 的重复注册由唯一 repository identity 拒绝；
4. 无引用项目可删除；存在 Session 或 Worktree 引用时明确拒绝删除。

结果：通过。

## T2.1-C2 Windows Native Git 记录

Registry 通过绝对 `System32\where.exe` 发现 Git，随后解析并 canonicalize `git.exe`。安装级能力不是按版本猜测，而是在隔离临时仓库实际执行：

- `git worktree list --porcelain`；
- `git status --porcelain=v2 -z`；
- `git lfs version`；
- `git config --bool core.symlinks`。

本机观测 Git 为 `2.47.1.windows.1`，Git LFS 为 `3.6.0`；路径、版本和四个布尔能力在 SQLite 写入/读取边界后保持一致。

结果：通过。

## T2.1-C3 环境一致性

统一验证器同时检查：

- Project.executionEnvironmentId；
- Runtime executionEnvironmentId；
- Git executionEnvironmentId；
- 可选 Worktree.executionEnvironmentId；
- Project root、Git root、canonical git dir、Runtime executable 和 Worktree path 的路径语义。

任一 Environment ID 不同即失败，不允许只因路径看似可访问而跨环境复用记录。

结果：通过。

## T2.1-C4 Windows/WSL 混用拒绝

路径分类器明确区分 Windows absolute、WSL UNC、WSL `/mnt`、一般 POSIX 和 relative path。负例覆盖：

- Windows Project + WSL Runtime ID；
- Windows Git ID + WSL Worktree ID/path；
- Windows Environment + `/usr/bin/codex`；
- Windows Environment + `/mnt/c/...`；
- Windows Environment + `\\wsl$\...`；
- WSL Environment + `C:\Tools\codex.exe`。

全部抛出 `EnvironmentBoundaryError`。

结果：通过。

## 失败与修正记录

1. 首次 TypeScript 编译发现 `??` 与 `||` 未加括号，改为明确的名称 fallback 分组后通过 strict 编译。
2. Project 测试首轮五个功能断言均通过，但 after hook 在 SQLite 关闭前删除临时目录，Windows 返回 EPERM。清理顺序改为先关闭数据库再删除经过固定前缀验证的临时目录，并清理 5 个本轮遗留 Fixture；修正后 6/6 通过。
3. Git 发现最初依赖 PATH 解析 `where.exe`；改为绝对 `%SystemRoot%\System32\where.exe`，减少当前目录/PATH 劫持面。
