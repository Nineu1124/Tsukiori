## 执行命令

所有真实运行都在随机临时 Git 仓库及其 Worktree 中进行。随机本机端口、Server 密码、原始事件、Prompt 和响应只存在于进程内或被忽略的私有目录。

```powershell
opencode --version
opencode auth list
opencode models dpsk
npm run test:opencode
npm run spike:opencode
npm run spike:opencode -- --model dpsk/deepseek-v4-flash --require-provider dpsk
pnpm install --offline --frozen-lockfile
npm run check
```

第一轮使用现有 OpenCode Go 能力完成协议预检；最终验收使用配置中的 `dpsk` Provider 发起真实 DeepSeek 请求。Harness 要求返回的 Provider 必须与 `--require-provider dpsk` 一致，因此不会把其他模型的成功误算为 DeepSeek Checkpoint。

## Checkpoint 证据

### T0.1-C1 Worktree Scope Server 生命周期

- 创建随机临时 Git 仓库和隔离 Worktree。
- OpenCode Server 绑定随机 `127.0.0.1` 端口，并使用随机密码和 Basic Authentication。
- `/global/health`、项目路径、VCS 探测和 `/doc` 均成功。
- Harness 在正常路径和异常路径的 `finally` 中停止 Server 并清理临时目录。
- 结果：通过。

### T0.1-C2 SDK 控制与独立 SSE

- 控制命令通过官方 SDK v2 客户端执行。
- 全局 SSE 使用独立订阅消费者，不复用控制请求响应通道。
- 观察到 `session.created`、`session.status`、`session.idle`、`message.updated` 等事件。
- 公开 Fixture 仅保留事件类型计数，不保留原始 payload、Session ID 或文本。
- 结果：通过。

### T0.1-C3 Permission、Cancel 与 Resume

- 安全命令触发 `permission.asked`，宿主回复后观察到 `permission.replied`。
- Permission 的类别为 `bash`，模式数量为 1；测试文件只在允许后出现。
- 一个活动 Turn 被 Abort，随后同一 Session 完成新的 Turn。
- 结果：通过。

### T0.1-C4 DeepSeek Provider

- 模型：`dpsk/deepseek-v4-flash`。
- Provider 来源：OpenCode 配置。
- 真实请求完成，模型出现在 Provider 的模型清单中。
- 数据出口主机为 `api.deepseek.com`。
- Harness 只记录识别到的 key-like 配置字段名 `provider.options.apiKey`；不读取、不打印、不写入字段值。
- 未发现依赖环境变量名。
- 结果：通过。

### T0.1-C5 崩溃与恢复边界

- Session 返回空闲后强制终止 Server 进程。
- 使用相同隔离项目目录重启 Server。
- 重启后可枚举原 Session，并读取其消息摘要，随后正常删除 Session。
- 本次未在 Turn 仍运行时强杀 Server，因此 `in_flight_turn_crash_recovery` 的 SupportLevel 与 EnforcementLevel 均为 `unknown`。
- 结果：通过；可恢复和未验证边界均已明确记录。

## 失败与修正记录

1. Permission 配置最初被当作标量传入，但 1.18.4 要求对象结构。Harness 改为显式目录拒绝策略。
2. 同步 Prompt 调用在一次采样中等待过久；改用异步 Turn，并通过 Session 状态与事件等待完成。
3. 部分空闲 Session 没有持续返回 status；Harness 将缺失状态和显式 idle 一并作为可开始下一次安全操作的条件。
4. SSE 消费者在 Server 停止前必须显式关闭；关闭逻辑移入 `finally`。
5. Provider 是否连接、模型是否列出只算配置证据；最终 Checkpoint 还要求指定 `dpsk` 的真实 Turn 成功。
6. 未测试运行中崩溃恢复，不降低验证标准，能力保持 `unknown`。

## 安全与脱敏

- 公开仓库不保存 API Key、Server 密码、认证文件、完整 Prompt、模型输出、用户源码或原始 Runtime 事件。
- 临时目录、认证头和常见令牌格式由 Harness 脱敏。
- Provider 证据只包含 Provider/Model ID、配置来源、字段位置和 endpoint hostname。
- 真实 Provider 测试仅在本机执行；公开 CI 只重放脱敏 Fixture。
- Worktree 提供变更隔离，不被视为安全沙箱。
