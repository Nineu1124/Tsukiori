## 结论

T2.4 的四个 Checkpoint 均已实现。新增 `@tsukiori/git-service`，以绑定到 Project Execution Environment 的系统 Git CLI 作为唯一事实来源。服务只接受 Session ID，并从 SQLite 解析 Session → Workspace Binding → Worktree → Project → Execution Environment；不接受任意 cwd，因此 Session 查询不会落到脏主工作区。

服务支持 porcelain v2 文件列表、Working Diff、Staged Diff 和 `baseCommit...HEAD` Session Commit Diff，并提供三段式 Session 总 Diff。所有 Git 调用通过 executable 与参数数组执行，固定 `shell: false`，仓库相对路径前固定 `--`。Diff 和文件大小有独立上限。

## T2.4-C1 文件列表和三类 Diff

文件列表使用：

```text
git -C <bound-worktree> status --porcelain=v2 -z --untracked-files=all
```

Diff 分别使用：

```text
git diff --no-ext-diff --no-color --binary
git diff --cached --no-ext-diff --no-color --binary
git diff <baseCommit>...HEAD --no-ext-diff --no-color --binary
```

真实测试依次修改、stage、commit 同一 tracked 文件，验证 working/staged/session-commit 内容和 HEAD/base commit。`sessionDiff()` 同时返回 commit、staged、working 三段，不把未提交改动伪装成 Session commit。

结果：通过。

## T2.4-C2 Rename、二进制、超大与未跟踪降级

porcelain v2 `2` record 使用 NUL 分隔解析，保留 rename/copy 的新路径和原路径。Diff 在返回内容前检查：

- binary：`--numstat -z` 出现 `-/-`，只返回 `binary` 元数据；
- large：工作树文件超过独立 file limit，只返回 `large` 元数据；
- untracked：Working Diff 不伪造 Git patch，只返回 `untracked` 元数据；
- output-limit：Git 输出超过 diff limit 时返回 `output-limit`，不返回不完整 patch；
- 无变化：返回 `not-changed`。

测试用 tracked binary、tracked large text、untracked text、rename 和单独的输出阈值覆盖每一种结果。

结果：通过。

## T2.4-C3 脏主工作区隔离

Fixture 在主工作区预先创建未跟踪文件，再创建独立 Session Worktree。Session 内修改 tracked 文件并创建新的未跟踪文件后：

- Git Status 只看到 Session Worktree 的文件；
- 主工作区 README 字节不变；
- Session-only 文件没有出现在主工作区；
- 主工作区原有 dirty 文件仍存在且保持未跟踪。

服务还核对 Binding path 与 WorktreeRecord path、Worktree owner Session、Project 和 Execution Environment，任一不一致即拒绝。

结果：通过。

## T2.4-C4 结构化 Git 参数

Git runner 固定：

- executable 来自 Execution Environment；
- args 为数组；
- `shell: false`；
- cwd 和 `-C` 均为绑定 Worktree；
- `GIT_PAGER=cat`、`GIT_TERMINAL_PROMPT=0`；
- 文件参数位于 `--` 之后；
- absolute、NUL 和 `..` 逃逸路径在执行 Git 前拒绝。

测试观察每次 invocation 并逐项断言，没有原始 Shell 字符串拼接。

结果：通过。

## 失败与修正记录

1. 首轮降级测试把 file limit 设为 256B，同时用超过 256B 的 README 验证 128B diff output limit，结果按设计先进入 `large`。测试改为使用独立的 8192B file limit 场景验证 `output-limit`，避免阈值遮蔽。
2. 为避免 Git 输出或文件内容进入持久层，本任务的 DiffResult 仅在调用内存中返回；公开 Fixture 和报告只保存能力与降级类别。

## 后续边界

- T2.4 是只读 Status/Diff 服务；Stage、Unstage、Commit 的产品 API 和审计属于 T4.4。
- Merge、Rebase、Conflict 和 Integration Worktree 属于 T4.5。
- 超限结果提供稳定元数据；外部编辑器打开动作由后续 UI/Native Control Plane 实现。
- Git Status/Diff 不提供安全沙箱，也不扩大 Runtime 对文件的权限。
