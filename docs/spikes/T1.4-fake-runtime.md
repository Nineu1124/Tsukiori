## 结论

T1.4 的五个 Checkpoint 均已实现。新增 `@tsukiori/runtime-core` 作为统一 Event Envelope、Normalizer、路由、去重、顺序、Connection Epoch、未知事件和恢复语义的纯核心包；新增 `@tsukiori/adapter-fake` 作为只有一个 Handle 事件读取器、可创建多 Session、可脚本化事件与断线的确定性 Runtime。

复用的 Adapter Contract Harness 同时驱动三个 Fake Session，每个 Session 按顺序产生 message started、text delta、tool started/completed、user input requested 和 message completed，共 18 个事件；Session ID 与 sessionSequence 完全隔离。异常测试覆盖重复、乱序、缓冲上限背压、Runtime Scope、未知协议事件、断线与旧 Epoch。未知事件在进入数据库前移除敏感字段名、替换凭据值、按字节限额并保留 SHA-256，随后作为 `native.event` 持久化；后续已知事件继续正常流动。

## T1.4-C1 多 Session 与流式事件

Contract Harness 创建三个 Session 并在同一个 Runtime Handle 事件读取器上运行。每个 Session 均产生六个标准事件，断言：

- `eventReaderCount === 1`；
- 三个 runtimeSessionId 唯一；
- 18 个事件只路由到所属 Session；
- 每个 Session 的 sessionSequence 独立为 1～6；
- 文本、Tool 与用户输入请求均映射为 Host Event Type。

结果：通过。

## T1.4-C2 故障与协议边缘注入

EventNormalizer 的每个路由维护独立 expected sequence 与有界 reorder buffer：

- sequence 2 先到：`buffered`；
- buffer 已满时 sequence 3：`backpressure`；
- sequence 1 到达：一次释放 1、2；
- 再次到达 sequence 1：`duplicate`；
- 未识别 native type：转为 `native.event`；
- 无 Session 的 Runtime state：scope 保持 `runtime`，不伪造 sessionId；
- disconnect：生成新 Connection Epoch 并清空旧 reorder/dedupe 状态。

结果：通过。

## T1.4-C3 Connection Epoch

Normalizer 只接受当前 epoch。测试先在 epoch A 接收事件，再断线切换到 epoch B：

- A 上迟到的 message completed 返回 `stale_epoch`，输出事件数为 0；
- B 上 sequence 1 正常接受；
- reconnect 事件记录 previous epoch，但不会执行旧响应、审批或状态变更。

结果：通过。

## T1.4-C4 未知事件保留、脱敏与限额

未知 Native Event 处理顺序：

1. 递归处理循环/不支持值；
2. 敏感字段名替换为无原名的 `redacted_field_N`；
3. Private Key、Bearer、`sk-` 等值替换为 `<redacted>`；
4. 对完整脱敏 JSON 计算 SHA-256；
5. 超过上限时只保留有界 preview 与 contentHash；
6. Envelope 标记 `redacted/truncated`，类型为 `native.event`；
7. 通过 `toSessionEventRecord` 进入 T1.3 数据库边界。

集成测试保存未知事件和紧随其后的已知 runtime state，关闭并重开 SQLite 后仍有两条；数据库内容不含测试凭据或原敏感字段名。

结果：通过。

## T1.4-C5 无补发能力时 Snapshot Recovery

Fake Adapter 可声明 `supportsEventReplay: false`。断线时：

- 所有 Session health 变为 `interrupted_runtime`；
- 生成 `runtime.warning`，原因 `event_replay_unavailable`、模式 `snapshot_recovery`；
- 每个 Session 生成带 `recoveredFromSnapshot: true` 的 state event；
- 不生成 text delta，不重放最后 Prompt 或外部副作用。

结果：通过。

## 失败与修正记录

1. Fake step 联合类型最初在 Runtime Scope 分支读取不存在的 runtimeTurnId。改为用 `kind === event` 判别后再复制 Turn ID。
2. 未知事件最初保留已脱敏字段的原敏感键名，会被 T1.3 数据库 Sink 的严格字段规则拒绝。Normalizer 现在同时移除敏感键名，集成持久化通过。
3. 截断后 redacted 标记最初只检查 preview，若敏感字段位于尾部可能误标 false。现在标记来自完整脱敏 JSON，截断不改变结论。
