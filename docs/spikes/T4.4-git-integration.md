# T4.4 V1 Git 操作与 Integration Worktree Merge 实施报告

## 结论

T4.4 的五个 Checkpoint 均已实现。Git Service 新增可审计的 Review、Stage、Unstage、Commit、Recovery Snapshot Revert；新增 `IntegrationMergeService`，默认在独立临时 Integration Worktree 执行 Merge/Rebase、验证和冲突处理，不在主工作区执行合并，也不自动更新目标分支。V1 Git UI 通过固定 Preload API 展示 Unstage、Snapshot Revert、Integration 验证、冲突继续和外部编辑器操作。

## T4.4-C1 Stage、Unstage、Commit 和 Session Commit Diff 可审计

每个显式操作先保存 `prepared` Operation，再进入 `running`，成功后为 `committed`，失败为 `failed/uncertain`：

- `git_review` 保存三类 Diff 是否可用、Base/Head Commit，`persistedDiffContent:false`；
- `git_stage` / `git_unstage` 保存绑定 Worktree ID、规范化相对路径和 Staged Count；
- `commit` 保存 Subject SHA-256、Staged Path、Previous/Result Commit，不保存原始 Subject；
- 所有命令使用参数数组、`shell:false`，路径参数位于 `--` 之后。

结果：通过。

## T4.4-C2 Revert 前恢复快照

Revert 不使用会先清空工作区的临时 Stash。实现使用独立 `GIT_INDEX_FILE`：

1. `read-tree HEAD`；
2. `git add -A` 把 tracked/untracked 当前状态写入临时 Index；
3. `write-tree` 和 `commit-tree` 创建恢复 Commit；
4. `update-ref refs/tsukiori/recovery/<opaque-id>` 固化快照；
5. 仅在快照成功后执行 `git restore` 与有界路径 `git clean -f -- <paths>`。

测试验证 tracked/untracked 字节均可从 Snapshot Commit 读取；在 Snapshot 后注入失败时，工作区字节不变，Operation 保留 Snapshot Ref/Commit。临时 Index/Lock 使用已验证的 Project Git Directory 内精确路径清理。

结果：通过。

## T4.4-C3 Integration Worktree 默认验证

`IntegrationMergeService` 从 Source Session 的 Workspace Binding 解析 Git、Project 和 Worktree：

- Source 必须 clean、无进行中 Merge/Rebase/Cherry-pick；
- Target Ref 解析为不可变 Commit；
- 在配置的 Integration Root 创建唯一 Worktree/Branch；
- Merge 或 Rebase 后运行结构化 Verification Commands；
- 成功后删除 Integration Worktree，保留 Integration Branch/Result Commit；
- 返回 `promotionRequired:true`，不更新目标 Ref；
- 主工作区 HEAD、文件和 Status 在测试前后完全一致。

结果：通过。

## T4.4-C4 冲突与外部编辑器

Merge/Rebase 非零退出时，服务仅在存在 `--diff-filter=U` 冲突路径时进入 `conflicted`：

- Operation 为 `uncertain`，Integration Worktree 保留；
- Attention Center 新增 `conflict`，包含 Operation ID、冲突相对路径和目录型 Editor Target；
- 外部编辑器调用要求绝对 executable、有限参数、`shell:false`，并对 Integration Path 做 canonical/Junction 校验；
- 用户在外部解决并 Stage 后调用 `continue()`；成功后关闭 Conflict Attention 并安全清理 Worktree。

Renderer 只传 Operation ID，不传任意路径或 executable；实际 Editor 配置与执行保留在 Host 侧。

结果：通过。

## T4.4-C5 Merge、Rebase、Submodule 与签名测试

真实 Git 集成覆盖：

- Merge commit：Source/Target 分叉后在 Integration Worktree 合并；
- Rebase：Source Commit rebase 到已前进 Target；
- Conflict：同一文件双边修改，保留、外部解决、Continue；
- Submodule：检测 index mode `160000`，在创建 Integration Worktree/Operation 前 fail-closed；
- Signing：Repository 设置 `commit.gpgSign=true` 和不存在的签名程序，服务以 `commit.gpgSign=false` / `--no-gpg-sign` 完成，证明不会静默拉起签名程序；
- Hooks/Editor：Integration 命令设置 `core.hooksPath=NUL`，Continue 使用非交互 Editor。

结果：通过。

## 安全边界

- Worktree 是隔离单元，不是安全沙箱。
- Git CLI 绑定 Project Execution Environment；不接受 Shell 字符串。
- Revert 是破坏性用户动作，但恢复快照先于任何删除。
- Verification Command 来自 Host 的结构化用户选择，限制数量和参数，不由 Runtime 输出直接执行。
- Integration 成功不自动更新 Target Branch；Promotion 需要后续明确确认。
- Submodule V1 fail-closed，不伪装支持。
- Diff、源码、Commit Subject 和 Runtime 输出不进入公开 Fixture。

## 失败与修正

1. Submodule 测试的 Gitlink 在工作目录中表现为缺失路径，最初先触发 clean-source 检查。实现把 Gitlink 检测移到 clean 检查前，使 Submodule 场景稳定、明确地 fail-closed，未降低清洁度要求。
2. Git Service 初版直接依赖 Permission Broker，包边界测试拒绝该反向依赖。改为最小 `IntegrationAttentionSink` 接口注入，保持冲突功能并恢复依赖方向。
3. CSS 插入首次产生字面 `` `r`n ``，静态核对后立即替换为真实换行，Renderer 语法与 Electron Smoke 通过。
