## 问题与纠正

此前 Desktop 普通模式固定返回空 Snapshot，所有 Workspace 命令仅在 `TSUKIORI_DESKTOP_SMOKE=1` 时返回成功。界面展示的是 Fake Runtime 工程 Fixture，不能添加项目、创建 Session 或发送 Prompt。因此，旧的 Local V1 Ready 只能证明组件和测试 Harness，不能证明产品可操作。

T5.6 新增真实交互 Workspace Controller 和 Codex app-server Client。普通模式不再复用 Fake Runtime Snapshot；Smoke Fixture 仅保留给无凭据回归测试。

### T5.6-C7 Daemon 子进程回收

- `daemon.ready` 和租约显式记录 `pipeHostPid`，Supervisor 对租约字段进行 fail-closed 校验；
- Named Pipe Host 使用 Daemon PID 与启动时间双重身份看门狗，父进程退出或 PID 复用时自行退出；
- `stop` 策略在 stdin 关闭、SIGTERM、SIGINT 与正常退出时等待回收 Pipe Host，超时后强制终止；
- `keep` 策略允许 GUI 释放后常驻 Daemon 继续服务，不把 stdin 关闭误判为产品退出；
- 自动化强杀 Daemon 连续 3 次，Pipe Host 均在 5 秒内退出；正常 stdin 关闭同样在 5 秒内退出；
- 完整宿主回归包含常驻 Daemon 重连、Renderer Crash、版本拒绝和 Pipe Host 回收，共 9/9 通过。

结果：通过。

- 交互 Local V1 当前以 Codex 为首个 Runtime；
- OpenCode Adapter 的既有协议验证仍保留，但不再被包装为普通模式已经接通；
