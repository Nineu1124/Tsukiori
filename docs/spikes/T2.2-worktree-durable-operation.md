# T2.2 Worktree 生命周期与 Durable Operation 实施报告

- 任务：T2.2
- 完成日期：2026-08-02
- 平台：Windows x64
- Worktree Manager：0.1.0
- 系统 Git：2.47.1.windows.1

## 结论

T2.2 的五个 Checkpoint 均已实现。新增 `@tsukiori/worktree-manager`，以当前 Execution Environment 的系统 Git CLI 创建和删除 Worktree。所有有副作用操作先写 `prepared`，再写 `running`，执行后核对文件系统、`git worktree list --porcelain` 和分支事实，最终写入 `committed`、`failed` 或 `uncertain`。恢复只核对事实，不自动重放 `git worktree add/remove`。

Worktree Root 可配置并 canonicalize；目标路径必须是 Root 的严格后代，限制为 220 字符，拒绝相对逃逸、Windows/WSL 混用和 Junction 逃逸。清理默认不使用 force：dirty、未跟踪文件或 active ProcessRecord 均阻止删除。

## T2.2-C1 Worktree Root 与路径边界

构造 Manager 时即验证配置 Root 属于 `windows-native`，创建后保存 canonical Root。目标目录规则：

- 必须是 Root 的严格后代，不能等于 Root；
- `directoryName` 只允许受限字符且拒绝 `.`/`..`；
- canonical parent 和创建后的 canonical target 再次做 descendant 检查；
- V1 路径上限为 220 字符；
- `/mnt/*` 和其他非 Windows path 被 T2.1 Environment Boundary 拒绝。

真实 Junction 负例将项目目录链接到 Root 外部，Manager 在 Git 执行前通过 realpath 发现逃逸并拒绝。

结果：通过。

## T2.2-C2 创建事实与 Operation 状态

创建流程记录：

1. Project、Session 与 Execution Environment；
2. base ref 解析出的固定 40/64 位 commit；
3. `agent/<runtime>/<session>-<slug>` 分支；
4. Worktree Root 和 target path；
5. Worktree ID、Operation ID 与 `prepared` 状态；
6. 外部动作前 `running`；
7. Git/文件系统事实一致后，在同一 SQLite transaction 写 Worktree 与 `committed`。

真实测试验证 Worktree HEAD 分支、数据库 base commit、Operation payload 和 Environment ID 一致。

结果：通过。

## T2.2-C3 创建/清理崩溃恢复

注入式 Daemon crash 点覆盖：

- create after prepared：无目录、无 Git registration、无分支 → `failed`；
- create partial branch only → `uncertain`；
- create after Git add：目录、registration 和预期分支齐全 → `committed` 并重建 WorktreeRecord；
- remove after prepared：目录和 registration 均存在 → `failed`；
- remove after Git remove：两者均消失 → `committed` 并标记 removed；
- remove partial filesystem only：文件系统与 Git registration 不一致 → `uncertain`。

恢复没有再次执行 add/remove。无效或不可读 Operation 也进入 `uncertain`，不会伪装为成功或无限 running。

结果：通过。

## T2.2-C4 默认拒绝 dirty/untracked 删除

清理使用结构化参数执行：

```text
git -C <worktree> status --porcelain=v2 -z --untracked-files=all
```

测试同时修改 tracked 文件并创建 untracked 文件，remove 明确失败、Operation 为 failed、路径仍存在。恢复 tracked 文件并删除 untracked Fixture 后，普通非 force remove 成功，WorktreeRecord 进入 removed。

结果：通过。

## T2.2-C5 PID 与 ProcessRecord 安全

清理发现所属 Session 有 `starting/running/stopping` ProcessRecord 时只拒绝删除，不调用任何进程终止 API。`ProcessIdentityGuard` 必须同时匹配：

- PID；
- daemonBootId；
- processStartTime；
- spawnNonce；
- 已记录 executable；
- 已记录 fingerprint。

测试模拟相同 PID 但 boot、启动时间、nonce、executable 和 fingerprint 均不同，以及 observed executable 缺失，两者都返回 false；Worktree 和分支保持存在。

结果：通过。

## 失败与修正记录

1. strict typecheck 首次发现 Git porcelain parser 在 exact optional 模式下可能写入 `head: undefined`。改为先收窄局部变量，仅在有值时创建字段。
2. Junction 负例首次未先创建链接目标，Windows 在 canonical 校验前返回 ENOENT。测试改为创建真实目标目录和 Junction，再验证 realpath 逃逸拒绝。
3. 外部 Git 命令开始后发生非注入异常最初会写 failed。为避免部分副作用被误判，现以 `externalAttempted` 区分：动作开始后异常写 uncertain，动作前检查失败才写 failed。
4. Process executable 最初只在 observed 也提供时比较；改为已记录 executable 时 observed 必须存在且完全匹配。

## 后续边界

- T2.2 不运行 Project setup/cleanup 动作；这些属于 T2.3。
- T2.2 保留分支，不自动判断未合并 Commit 是否可丢弃；相关用户流程在 T2.3/T2.4 完成。
- 进程停止属于受 Process Supervisor 保护的独立动作；Worktree cleanup 不以猜测身份自动杀进程。
- 自动备份、全局恢复 UI 和长期 orphan 扫描属于 T5。
- Worktree 是代码隔离，不是安全沙箱。
