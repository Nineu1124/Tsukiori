# T-LT-D017：MCP 保存失败回滚

实际完成：2026-10-16；Windows，Node 24.11.1。

正式保存和删除入口先准备所有项目配置、管理记录与登记文件，全部校验后逐个原子替换。登记文件最后写入，内存只在文件全部成功后更新。发生替换失败时按反向顺序恢复旧文件；不再出现界面登记成功但项目配置失败的状态。损坏登记文件拒绝加载，不降级为空列表。

验证：桌面本地 TypeScript 编译通过；MCP 与能力回归 21/21。对更新、删除分别注入配置、管理记录、登记文件的 rename 失败，逐字节比较回滚结果并重启核对登记；冲突不会留下新登记。提交前运行 `npm run check`、`git diff --check`。

此处保证进程内可恢复 I/O 失败的回滚，多个文件不是文件系统级原子事务。断电或磁盘同时拒绝回滚不在已验证保证内；后者明确报保存及回滚失败，不能当成成功。后续统一存储阶段仍需持久事务机制。
