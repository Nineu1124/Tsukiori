## 问题与纠正

T5.6 只实现了浅色三栏布局与 Codex 闭环，但设置入口缺失，Runtime/Model/Environment/Permission 是禁用占位，Provider/API 无法配置，右侧工作面板也没有设计稿要求的四入口信息架构。Codex `userMessage` 同时被错误映射为 READ Tool Card。

本任务把设置与 Provider 提升为正式领域对象，增加 Codex/Claude Code Runtime 选择，并按 34 页设计规范重新实现 Desktop。Lody 的 ACP/Settings 分层和 cc-haha 的 Provider-first 配置只用于理解产品边界；Tsukiori 使用自己的 IPC、数据结构、凭据绑定和视觉组件。

## Checkpoint 证据

### T5.7-C1 设置中心

- 左下角齿轮、`Ctrl+,` 和设置弹窗关闭入口均可操作；
- 一级导航包含通用、外观、账号、Agent、用量、项目、设备、GitHub、键盘快捷键、账单和关于；
- 通用与外观设置写入 `workspace-state-v2.json` 并在重启后恢复；
- Agent 页面提供 Provider 编辑、连接测试和 Runtime 重新探测；
- 用量只统计本地 Session/Turn，不虚构 Provider 账单。

结果：通过。

### T5.7-C2 Provider Registry 与 API

- 内置 ChatGPT 登录、OpenAI、Anthropic 和 DeepSeek；
- 支持自定义 OpenAI-compatible 与 Anthropic-compatible；
- 每项包含名称、Base URL、Model 列表、启用状态、连接测试、编辑和删除；
- OpenAI-compatible 连接测试调用 `/v1/models`；Anthropic-compatible 使用 `max_tokens=1` 的显式测试请求；
- 连接结果只记录布尔值、延迟和错误类别，响应 Body 立即丢弃。

真实 Provider 状态：Codex 使用现有 ChatGPT 登录的隔离 Probe 通过；本机未配置 Anthropic、DeepSeek 或额外 OpenAI API Key，因此这些 Provider 在 UI 中显示“需要 API Key”，未伪造为已连接。连接协议由无凭据替身测试验证。

结果：通过。

### T5.7-C3 Credential Manager

### T5.7-C4 Runtime Registry

## 能力边界

- Claude Code 当前 Bridge 是官方 CLI `stream-json`，完整 ACP 权限协商仍属于 B1；
- OpenCode 和 Generic ACP 没有因本任务而提升为可操作 Runtime；
- 自定义 OpenAI-compatible Provider 必须实现 Codex 所需的 Responses API；不兼容的 Chat Completions-only 服务会在连接或 Turn 时明确失败；
- Worktree 继续是变更隔离机制，不是安全沙箱；
- 真实 API Provider 测试由用户在设置页显式触发，公开 CI 不持有用户凭据。
