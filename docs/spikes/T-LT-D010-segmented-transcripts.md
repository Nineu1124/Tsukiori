# T-LT-D010：分段 Transcript

实际完成：2026-09-28。Windows；Node 24.11.1；沿用锁文件依赖。

删除 5 MiB 静默停写和 8 MiB 静默跳过逻辑。单段默认 4 MiB，完整事件不拆分；超过目标大小的单条记录独占一段。上限为单条 16 MiB、索引 1 MiB，触及时明确报错。读入按 64 KiB 分块，UI 只留有界事件缓存，模型消息仍完整重建。

首次轮转保留原 JSONL，通过原子更新 `.index.json` 发布新分段；索引只允许当前 Transcript 的文件名，缺段或损坏不退回旧文件。Checkpoint 读取所有有效分段，回退原子切换索引，旧段保留但不再参与读取。Checkpoint 本身继续执行明确的 8 MiB 总量限制，没有扩大 Git 快照能力。旧单文件快照保持原始换行哈希兼容。

保存失败产生固定警告，Session 标记 `transcriptIncomplete`，阻止下一轮以不完整记录继续；该标记随工作区状态保存。读取损坏行也会标记异常，不能再忽略坏行后把历史当完整。磁盘连状态文件也无法写入时，只能保证当前进程内可见警告，不能保证异常标记跨断电保存。普通追加没有逐事件 fsync 保证。

验证：`npm run build` 21/21、`npm run typecheck` 34/34；Transcript、Checkpoint、API 历史三组 11/11。覆盖超过 9 MiB 的多段读回、UTF-8 跨块、旧文件缺末尾换行、路径穿越、缺段、单条超限、索引替换失败、回退和撤销回退、保存失败及重启阻断。提交前执行 `npm run check`、`git diff --check`。

退役段和索引发布前留下的孤立段暂不自动清理；备份应复制整个 transcripts 目录。没有执行断电或真实磁盘满实验，I/O 替换失败通过故障注入验证。
