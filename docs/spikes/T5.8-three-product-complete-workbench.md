- 日期：2026-08-03
- 平台：Windows Native x64
- 参考对象：Codex Desk `0.1.4`、Lody `0.75.1`、cc-haha `0.5.1`

## 范围与许可边界

三个应用只作为只读产品研究对象。分析内容包括安装包的 `package.json`、公开许可文件、模块/资源名称、可访问 UI 结构和用户可见功能；没有复制参考项目的源文件、压缩 Bundle、品牌名、图标、插画、Prompt、认证状态、会话正文或用户路径。临时解析物只存在 `.gitignore` 排除的 `.tmp/reference-audit`。

Codex Desk 的包内许可为 MIT，可观察模式包括官方 Codex app-server、项目/任务导航、Worktree、Skills、扩展、内嵌浏览、Computer Use 和 Agent Team。Lody 的可观察模式包括 ACP SDK、CLI Supervisor、多 Runtime、远程/本地预览和协作任务；其包未声明可供本项目复用的源码许可，因此仅记录产品模式。cc-haha 的可观察模式包括 Claude 工作流、node-pty/xterm、富 Markdown、Mermaid、Diff、远程 H5 和启动失败自诊断；同样不复制其 Bundle 或品牌资产。

## T5.8-C1 参考产品审计

只读检查命令使用固定安装路径和本仓库锁定的 `@electron/asar`，输出仅用于当次分析。公开仓库未新增参考应用文件，秘密扫描也不扫描或提交用户配置目录。

结果：通过。

## T5.8-C2 Session 与 Transcript

- Session 增加 `updatedAt`、`pinned`、`archivedAt`；列表支持搜索和置顶排序；
- 重命名、置顶、归档均由 Main Process 调用领域方法；运行中 Session 拒绝归档；
- 归档只更新状态并保留 Worktree，不调用 `git worktree remove`；
- `workspace-state-v3.json` 保存结构化状态，正文进入独立 `transcripts/<sha256(sessionId)>.jsonl`；
- Transcript 只在用户设置允许时写入，单 Session 上限 5 MiB，重启最多恢复最后 1000 个安全公共事件；
- API Key、Credential Reference 和 Provider 响应正文不写入 Transcript。

结果：通过。

## T5.8-C3 文件、附件与富内容

- 文件枚举忽略 `.git`、`node_modules` 和 `.turbo`，最多返回 2000 项；
- 文本预览必须通过 canonical path containment，最大读取 512 KiB，二进制和 `..` 越界路径失败；
- 附件由 Electron 文件选择器产生可信选择，每次最多 10 个、每个小于 10 MiB，复制到 `.tsukiori/attachments`；
- Renderer 只使用 `textContent` 和安全 DOM 节点实现 Markdown、标题、列表、引用、行内代码与代码块，没有 `innerHTML`、`eval` 或 Node 权限；
- 链接交回 Main Process 的 HTTP/HTTPS URL 校验。

结果：通过。

## T5.8-C4 ConPTY 与预览

- `TerminalManager` 为每个 Session 在其 Worktree 启动 Windows PowerShell ConPTY；
- 输入单次上限 8192 bytes，输出事件单块上限 32768 字符，Renderer 总显示上限 500000 字符并移除 ANSI 控制序列；
- 终端环境过滤名称含 `TOKEN`、`SECRET`、`PASSWORD`、`API_KEY`、`AUTH` 的变量；
- 独立 Probe 使用仓库 T0.3 已验证的交互式写入、显式 `exit` 和独立子进程退出方式；
- 预览 iframe 只允许 HTTP/HTTPS，CSP 约束为 localhost、127.0.0.1 和 HTTPS，iframe 使用 `sandbox="allow-scripts allow-forms allow-same-origin"`，无 Preload/Node 桥。

结果：通过。

## T5.8-C5 Skills、MCP 与 Agent Team

- Codex Session 按用户动作读取 `skills/list` 与 `mcpServerStatus/list`；
- UI 仅得到 Skill 名称/描述/启用状态/Scope 和 MCP 名称/Auth Status/计数，不保存原始路径、Schema、Token 或响应正文；
- Team 只接受 2–4 个成员，每个成员通过正式 `createSession` 创建独立分支和 Worktree；
- Provider 兼容性、密钥存在性和 Runtime 可用性仍在创建 Worktree 前验证；
- 派发失败记录 `partial_failure`，不会伪装成成功，也不会自动删除已产生的 Worktree。

结果：通过。

## T5.8-C6 设置、更新、GitHub 与品牌

- 通用设置增加本地对话持久化和高风险确认策略；
- 公开 Release 检查只访问 GitHub 官方 API，10 秒超时，校验 SemVer 和 `github.com` Release URL；
- Git/GitHub 状态只返回用户显示名、分支、远程 Host/Repository 和 `gh` 是否登录，不返回 Token、Cookie 或凭据路径；
- Windows 包配置正式使用本项目生成的蓝白星辉几何图标，不再使用 Electron 默认图标；
- 视觉严格使用设计稿的 40px 标题栏、300px 左/右栏、620px 中央最小宽度、820px 会话内容上限、220px 终端、蓝白高明度色板和几何装饰；正文提升到 13–15px，辅助信息保持 11–13px；
- 1040×720 紧凑窗口下左栏收敛到 240px，右侧工作面板改为 360px 覆盖层，不压缩中央会话；
- 所有按钮都有统一 Hover、按压、Focus 和 Disabled 反馈；发送、终端、Agent Team、中断、危险操作、侧栏卡片与弹窗有克制的专属动画；系统或用户启用减少动态效果时停止位移、扫光和呼吸动画。

结果：通过。

T5.8 将三个参考产品的核心优点落实为 Tsukiori 自有实现，同时保留能力真实性边界：Codex 为 `supported`，Claude Code CLI 为 `degraded`，OpenCode 与 Generic ACP 仍为 `unknown`。Worktree 继续是变更隔离而非安全沙箱；Terminal 是用户直接控制的本地 shell，不伪装成 Runtime Approval 沙箱。
