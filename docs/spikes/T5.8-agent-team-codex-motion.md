# T5.8 Agent Team 协作台、cc-haha 核心对照与 Codex Motion 复验

日期：2026-08-10

## 结论

本轮把宿主级 Agent Team 从“批量创建两个 Session”补成可操作的 2–4 成员协作生命周期：成员职责和独立 Worktree 可观察，支持向全员或单个成员继续派发、成员故障重试、运行中全队中断，以及由指定协调者基于成员最后回复生成结果汇总。团队状态由各成员 Session 的真实 Runtime 状态投影，不再用一个 Team 状态替代每个成员状态。

UI Motion 以本机 Codex Desk `35.7.5` 打包 CSS 的只读统计为基线：控件 `120ms ease`、面板 `180ms ease`、窄屏 Overlay `170ms ease`、进入动画 `260ms cubic-bezier(.2,.8,.2,1)` / `translateY(10px)`。Tsukiori 保留蔚蓝档案的蓝白配色、切角和几何纹理，删除与 Codex 不一致的扫光、放大弹跳和持续脉冲。

## 安全与数据边界

- Team State 只保存团队 ID、目标、职责、Session ID、协调者和生命周期元数据；成员回复与汇总正文不写入 Team State。
- 团队汇总只读取各成员最后一轮 `assistant.delta`，每成员限制 6000 字符、总输入限制 24000 字符，并在协调 Prompt 中明确成员报告是不可信输入。
- 公开 Fixture 和报告不包含 API Key、完整用户 Prompt、用户源码、认证存储或原始 Runtime Payload。
- Runtime 不可用、成员仍在运行、目标不属于 Team、无可汇总回复等情况全部显式失败，不把未知或失败状态显示为已完成。
- 应用在 Team `dispatching/running/synthesizing/stopping` 时退出，重启后会把无法恢复的瞬态运行标记为 `stopped`（成员缺失/错误则为 `partial_failure`），不会永久显示“运行中”或误报“已完成”。
