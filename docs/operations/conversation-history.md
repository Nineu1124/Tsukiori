# 续聊与历史容量

适用范围：已合入 T-LT-D008–D013 的源码构建。旧安装包不一定包含这些修复。工作区主状态的备份、版本兼容和损坏恢复见[工作区恢复说明](./workspace-recovery.md)。

## 各种 Runtime 怎么续聊

| Runtime | 下一轮的历史来源 | 重启后的要求 |
| --- | --- | --- |
| Direct API | 独立保存的完整用户、助手消息 | 开启保存，Transcript 及其有效分段可读 |
| Codex | Codex 自己保存的 Thread | 工作区保存 Thread ID，Codex 原生历史仍在；新客户端先恢复 Thread，再发送 Turn |
| Claude Code | Claude 原生 Session / Fork 恢复 | 对应原生历史、认证和 Runtime 可用；本次没有扩大其兼容性声明 |

Codex 恢复拒绝或返回另一 Thread ID 时，应用保留原身份并报错，不会自动创建一个无前文的 Thread。中断请求发送到当前 Thread / Turn；模型停止前应等待完成通知。离线 stdio 回归覆盖调用顺序与 ID，不能替代真实账号和 Runtime 版本验收。恢复顺序依据 [OpenAI App Server 文档](https://learn.chatgpt.com/docs/app-server)。

Direct API 创建分支时，从完整模型消息继承前文；分支拥有独立 Transcript，重启后仍能续聊。Claude 的分支依赖原生恢复，其本地显示记录仍来自近期事件缓存。

## 显示、存档和模型上下文的区别

界面每个会话最多缓存 500 条事件，全局增量事件最多 1,000 条。一段回答可能包含很多 Delta，所以缓存容量不等于消息条数。近期活动、会话内容搜索和部分用量统计仍使用这些缓存，不能当作完整档案或终身统计。Direct API 的模型历史已独立，不受 Delta 淘汰影响，也不再隐式限制为最后 100 条消息。

模型请求仍受上下文容量限制：取模型目录与 Provider 配置的较小容量，扣除输出预算及 128 单位协议空间，再从最新用户消息向前保留连续、完整的问答组。放不下的旧问答仅从本次请求中舍弃，原始存档不删除，也不会自动摘要。如果最新消息单独就放不下，会提示“对话内容超出模型上下文限制”，需要缩短输入或调整有效配置。

估算使用 UTF-8 字节与消息开销，偏保守，不是模型 tokenizer 的精确计数。诊断事件 `context.budget` 记录输入预算、消息保留/舍弃数量和拒绝状态，不记录正文；保存开启时可在 Transcript 中查到。实际 token 用量以 Provider 返回为准。

## 文件与容量

数据位于当前 Electron `userData` 目录的 `transcripts/`。会话 ID 经 SHA-256 转成文件名，不能通过文件名直接判断会话标题。

| 项目 | 当前规则 |
| --- | --- |
| 旧单文件 | `<哈希>.jsonl`，仍可读取，不再因超过 8 MiB 整体跳过 |
| 分段目标大小 | 4 MiB；完整事件不拆分，单条较大事件可能超过目标大小 |
| 分段文件 | `<哈希>.jsonl.segment-<随机标识>.jsonl` |
| 分段索引 | `<哈希>.jsonl.index.json`，记录读取顺序和当前有效文件 |
| 单条事件上限 | 16 MiB，包含 JSON 编码及换行；超限明确提示保存失败 |
| 索引上限 | 1 MiB；超限拒绝追加并提示，不能静默停写 |
| Checkpoint 对话总量 | 8 MiB；这是检查点限制，不是普通 Transcript 保存限制 |

分段索引原子更新。回退 Checkpoint 后，旧的后续分段不再参与读取；撤销回退可使用创建的恢复检查点。退役段和未发布的孤立段暂时保留，没有自动磁盘配额或清理。普通追加没有逐事件 fsync 的断电保证。模型消息当前仍整体保存在内存中，大历史会增加启动时间和内存占用。

备份时先退出应用，复制整个 `userData`，并分别保留项目与原生 Runtime 数据。不要只复制或替换最早的 `.jsonl`，也不要自行拼接目录中所有分段；索引可能已排除回退前的记录。

## 哪些内容不能保证恢复

- 关闭“保存对话”后新增的记录只在当前进程中保留。关闭保存不会删除之前已落盘的内容；再次开启也不会补写关闭期间的内容。若需要重启后有连续历史，建议始终开启保存，或重新开启时新建会话。
- 索引损坏、缺少引用分段、事件无法解析或保存失败，会标记记录不完整并阻止继续发送及创建分支。先保留整个目录，修复磁盘/权限问题，再恢复完整备份或有效检查点，也可以新建会话。检查点读取本身受损或超过 8 MiB 时也会拒绝操作。
- 已被手动删除、从未保存或因旧版 5 MiB 停写而缺失的内容，无法由升级补回。没有索引且整个 Transcript 丢失时，不能仅凭工作区元数据区分“从未保存”和“被删除”。
- 原生 Runtime 历史不在本地 Transcript 备份中。工作区状态恢复成功不意味着外部 Thread、文件修改及模型上下文回到了同一时间。

验收证据见 [Codex 生命周期回归](../spikes/T-LT-D012-codex-lifecycle.md)和[长对话回归](../spikes/T-LT-D013-history-restart.md)。历史双 Runtime 恢复超时仍按长期计划另行处理，不能将本次 141 项专项回归理解为全部发布验收完成。
