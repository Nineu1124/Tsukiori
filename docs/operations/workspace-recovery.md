# 工作区恢复说明

适用范围：已合入 T-LT-D001–D006 的源码构建。旧安装包可能没有这些保护，不能仅凭版本名称判断。

## 数据位置与备份

桌面入口使用 Electron `app.getPath('userData')`，具体目录取决于应用名称和运行方式。确认当前构建实际使用的目录后，先退出桌面程序，再复制整个目录到独立备份位置；不要在程序写入期间替换文件。项目原目录和外部 Runtime 的历史、凭据目录需要分别备份。

| 文件或目录 | 用途 |
| --- | --- |
| `workspace-state-v3.json` | 项目、会话、设置等元数据 |
| `workspace-state-v3.json.bak` | 最近一代有效状态备份；不是完整数据备份 |
| `workspace-state-v3.json.corrupt-<随机标识>` | 自动恢复前保留的损坏原文件 |
| `transcripts/` | 开启对话保存时写入的会话记录 |
| `worktrees/` | 独立工作目录，可能包含尚未提交的代码 |

保存状态时先写同目录临时文件、刷新并替换，保留上一代有效状态。读取失败不会按空工作区覆盖原文件。原子替换测试覆盖写入、刷新和替换失败；没有模拟所有硬件断电或文件系统故障。

## 启动异常怎么处理

1. JSON 损坏或主文件丢失，但备份有效：应用自动恢复，并在桌面显示恢复提示。检查项目、会话和设置是否符合预期；备份可能比最后一次操作旧。损坏主文件会另存，不应立即删除。
2. 主文件和备份都损坏：启动会报错。保留两份文件及整个用户目录，从独立备份恢复，或在副本上排查。不要用空 JSON 覆盖，也不要盲删状态文件来“重置”。
3. 权限不足、文件无法读取：先退出重复运行的实例，确认当前账户能访问该目录，排查权限或文件占用。应用不会用备份掩盖此类读取错误。
4. 文件版本比程序支持的更新：使用写入它的兼容版本。不要手改版本号，也不要退回旧版状态文件；旧程序会拒绝未知版本。

只有主状态及其备份均不存在时，才按迁移顺序尝试 v2、v1。状态恢复不代表 Transcript、Runtime Thread 或 Git 工作目录同步回到了同一时刻。关闭“保存对话”后产生的内容没有重启恢复保证。
